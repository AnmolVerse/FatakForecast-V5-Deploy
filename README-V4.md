# FatakForecast V4 (Historical)

> **Note:** FatakForecast has been upgraded to **V5**. Please refer to the root [`README.md`](README.md) for the complete V5 architecture, ML pipeline, simulation harness, and test suites.

## Backend setup
1. Open `FatakForecast/backend` in VS Code terminal.
2. Create `.env` from `.env.example`.
3. Set `RAILRADAR_API_KEY=...`.
4. Run `npm install`.
5. Run `npm run check`.
6. Run `npm run test:offline`.
7. Run `npm run monitor`.

## Important V4 geometry rule
Train position and crossing position are both projected onto the same RailRadar GeoJSON LineString. RailRadar route `distance` values are never mixed with GeoJSON `locationKm` for crossing arithmetic. This prevents the scale mismatch seen in earlier builds.

## Data reset
The active JSON datasets are intentionally empty for V4. Legacy observations/events generated by earlier builds are stored under `backend/data/legacy-v1-v3/` and are not used by the active predictor. This prevents old coordinate-system data from contaminating V4.

## API key security
Never commit `.env` or send the API key in screenshots. If a key has been exposed, rotate it in RailRadar and replace the value locally.


## V5 prediction and learning changes

- Initial closure baseline: **11 minutes before predicted train passage**.
- Initial reopening baseline: **1 minute after predicted train passage**.
- The 11/1 values are priors, not ground truth.
- Verified gate observations are collected through `POST /api/observations`.
- With one or more verified observations, the predictor applies a crossing/direction-specific gradual correction toward the 11-minute prior.
- A first ML layer uses ridge regression only after at least 20 verified observations and only when its chronological held-out MAE beats the 11-minute baseline by at least 5%. Otherwise the statistical baseline remains active.
- Do not train on the forecast's own 11-minute estimates. Those are predictions, not labels.
- Gate feedback should contain actual gate-close time and actual train-passage time; actual gate-open time is optional but useful.
- Production deployment must provide `RAILRADAR_API_KEY` through the host's secret/environment settings. Never package `backend/.env`.
